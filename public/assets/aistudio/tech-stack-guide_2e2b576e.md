# GitHub Pages — Developer Guide for Chess Opening Trainer

## 1. What GitHub Pages Actually Is

GitHub Pages is **static hosting only**.

It takes files from your repo (`main` branch) and serves them as a website. There is no server running your code. No Node.js, no Python, no database, no server-side logic.

**Mental model:** Think of it as a public folder on the internet. If it can run in the browser, it works. If it needs a server, it doesn't.

Live URL will be:
`https://<username>.github.io/<repo-name>/`

## 2. Approved Tech Stack — Use ONLY This

| Layer | Use This | Why It Works on Pages |
| :--- | :--- | :--- |
| **Language** | HTML, CSS, Vanilla JavaScript (ES Modules) | Runs 100% in browser, no build step needed |
| **Chess Rules** | `chess.js` via local file or ES Module CDN | Pure JS logic, no server |
| **Board UI** | Custom CSS Grid + SVG pieces in `/assets/pieces/` | No dependencies, no jQuery |
| **Content** | Markdown files in `/lines/` | Just text files, fetched with `fetch()` |
| **Index** | `manifest.json` generated by GitHub Actions | Pages can't list folders, so we generate the list |
| **Engine (M4 Only)** | Stockfish WASM single-threaded, vendored in `/engine/` | Runs in Web Worker in browser |
| **Styling** | Plain CSS or Tailwind via CDN (optional) | No build step |
| **Hosting** | GitHub Pages from `main` branch | Free, auto-deploys on push |

### What to Install
**Nothing.** No `npm install`, no `npm run build`, no Vite, no Next.js, no React build step for MVP.

If you need a library, you have 2 allowed ways:
1.  **Vendored:** Download the `.js` file and put it in `/libs/` in the repo. Best for `chess.js` and Stockfish.
2.  **ES Module CDN:** `import ... from "https://cdn.jsdelivr.net/..."` — Allowed, but risky if CDN goes down. Prefer vendored for core logic.

## 3. What You CAN Do

**You CAN:**
1.  Build a full Single Page App in vanilla JS. All state lives in `app.js`.
2.  Fetch files from your own repo: `fetch('manifest.json')`, `fetch('lines/queens-gambit.md')`.
3.  Use `localStorage` to save progress: `lastOpening`, `lastVariation`, `mistakesByVariation`. This is your ONLY database.
4.  Use GitHub Actions to auto-generate files. Example: When a `.md` file is pushed to `/lines/`, Actions rebuilds `manifest.json` and commits it back.
5.  Use Web Workers for Stockfish. The engine runs in the browser, not on a server.
6.  Use a custom domain later (e.g., `chess.yourdomain.com`) via a `CNAME` file.
7.  Use client-side routing with `#hash` (e.g., `#/queens-gambit/accepted`). Do NOT use `/path` routing.
8.  Make it a PWA later with a Service Worker for offline use (still static files).

## 4. What You CANNOT Do — Hard Limits

This is where most developers fail. **Do NOT try these:**

**1. NO Backend / NO Server Code**
- ❌ No Node.js, Express, Python Flask, PHP, Ruby
- ❌ No `app.post('/save-progress')`
- ❌ No API routes

**2. NO Database**
- ❌ No PostgreSQL, MongoDB, Firebase, Supabase (as a direct server DB)
- ❌ No user accounts, no login, no signup
- ✅ Workaround: `localStorage` for per-device progress only. If user clears browser, progress is gone. That's acceptable for MVP.

**3. NO Secrets / NO API Keys**
- ❌ Never put an API key, password, or token in JS. Everything in the repo is public and visible in DevTools.
- ✅ If you need an external API later, it must be a public, keyless API, called directly from the browser.

**4. NO Dynamic File Listing**
- ❌ `fetch('/lines/')` will NOT return a list of files. GitHub Pages returns 404.
- ✅ Workaround: You MUST use `manifest.json`. The app never guesses filenames, it reads the manifest.

**5. NO Server-Side Headers / CORS Config**
- ❌ You cannot set `Cross-Origin-Opener-Policy` or `SharedArrayBuffer` headers. GitHub Pages doesn't let you.
- ✅ Consequence: You CANNOT use multi-threaded Stockfish. You MUST use single-threaded WASM only. This is why your plan says M4 = single-threaded.

**6. NO Private Repos (on Free Plan)**
- GitHub Pages on a free account requires a **public repo** to publish. Your code and your `.md` opening files will be public. Don't put private lines in there.

**7. NO Large Files**
- ❌ GitHub limit: 1GB repo soft limit, 100MB per file hard limit. Pages site limit is 1GB.
- ✅ Your app is tiny (<5MB). Keep Stockfish WASM files vendored but check size — keep them under 30MB total.

**8. NO Build-Time Secrets in Actions**
- GitHub Actions CAN write to the repo, but you must use `[skip ci]` in the commit message when Actions commits `manifest.json`, otherwise it will trigger itself in an infinite loop.

## 5. File Structure Rules for GitHub Pages

```
/index.html          // MUST be at root, this is the entry point
/style.css
/app.js
/parser.js
manifest.json        // Generated, never edit by hand
/lines/*.md          // Content files
/assets/pieces/*.svg
/engine/*           // Stockfish files (M4 only)
.github/workflows/build-manifest.yml
```

**Critical Rules:**
1.  All links must be **relative**: `fetch('manifest.json')`, NOT `fetch('/manifest.json')`. Absolute `/` breaks when hosted at `username.github.io/repo-name/`.
2.  All file names must be **lowercase, no spaces**: `queens-gambit.md`, NOT `Queen's Gambit.md`.
3.  `index.html` must reference JS with `<script type="module" src="./app.js">` or plain `<script src="./app.js">`.

## 6. Developer Workflow

1.  Clone repo, open `index.html` with Live Server in VS Code (or `npx serve .`).
2.  Edit code / add `.md` file in `/lines/`.
3.  Push to `main`.
4.  GitHub Actions runs: rebuilds `manifest.json` -> commits with `[skip ci]` -> Pages redeploys in ~1 min.
5.  Hard refresh live site (Ctrl+Shift+R) to bypass cache.

**Caching Gotcha:** GitHub Pages caches aggressively. In `app.js` you MUST use:
```js
fetch('manifest.json', { cache: 'no-store' })
```

## 7. Quick Decision Checklist for Developer

When they want to add a feature, ask:

> "Can this run 100% in the browser with only files in this repo + localStorage?"

- **Yes** -> Allowed. Build it.
- **No, needs a server / DB / login / secret** -> NOT allowed. Cut it from MVP or move it to Post-MVP with a different host.
